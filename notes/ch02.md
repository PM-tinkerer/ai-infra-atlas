# 第 2 章｜GPU 架构：大模型计算如何映射到硬件

## 1 GPU 执行与任务组织

### CPU 与 GPU 分工

一轮推理包含输入组织、取数、计算和结果传递。GPU 架构决定任务如何分配、数据如何供给，以及计算如何持续推进；三者共同影响对话、长文档与 Agent 请求。

词元（Token）是文本处理单位，权重（Weights）是训练得到的参数，激活（Activations）是逐层产生的中间数值。推理复用权重、更新激活。

中央处理器（Central Processing Unit，CPU）负责请求、输入、批次和提交；图形处理器（Graphics Processing Unit，GPU）并行执行大量相似数值运算。模型权重通常在启动时载入显存，供后续轮次复用。

本章以 NVIDIA GPU、CUDA 编程平台说明结构；其他加速器的执行单元和实现须按目标架构确认。 [来源：CUDA 12.6 编程指南，异构计算；核验于 2026-11-16](https://docs.nvidia.com/cuda/archive/12.6.0/cuda-c-programming-guide/index.html#heterogeneous-programming)

### 算子、核函数与线程层次

算子（Operator）是矩阵乘法、归一化等数学操作，核函数（Kernel）是执行设备工作的程序。引擎选择、提交 Kernel；一个算子可拆成多个 Kernel，多个算子也可融合。

NVIDIA GPU 的多个流式多处理器（Streaming Multiprocessor，SM）并行执行任务，各自具备指令执行、临时存储与调度资源。

CUDA 将工作组织为以下层次：

| 名称 | 含义 | 在一次计算中的作用 |
| --- | --- | --- |
| 线程（Thread） | 一个逻辑执行单元 | 处理分配给自己的数据和计算步骤 |
| 线程块（Block） | 一组协作线程 | 共同加载数据、交换中间结果并同步 |
| 网格（Grid） | 一次核函数启动的全部线程块 | 覆盖本次提交的完整计算任务 |
| 线程束（Warp） | 同一线程块内的一组线程；NVIDIA 中为 32 个线程 | SM 按线程束组织指令执行 |

**软件划分线程、线程块，硬件将线程块分配到 SM。** 普通 CUDA 块在单个 SM 上执行；资源允许时可驻留多个块，完成后释放资源供后续块使用。 [来源：CUDA 12.6 编程指南，线程层次与硬件实现](https://docs.nvidia.com/cuda/archive/12.6.0/cuda-c-programming-guide/index.html#thread-hierarchy)

### SIMT 与分支分歧

单指令多线程（Single Instruction, Multiple Threads，SIMT）让同线程束的线程通常执行相同指令、处理不同数据，如并行逐元素加法。

分支分歧（Divergence）使线程束内不同路径分阶段执行，降低部分阶段的并行效率；规则矩阵工作更适合成组执行。 [来源：CUDA 12.6 编程指南，SIMT 架构](https://docs.nvidia.com/cuda/archive/12.6.0/cuda-c-programming-guide/index.html#simt-architecture)

并行任务进入 SM 后，持续执行还取决于数据供给。

## 2 存储层次与数据供给

### 显存、缓存与片上资源

存储系统以不同层次兼顾大容量驻留和快速供数：权重、状态常驻显存，当前计算的数据在片上复用。

片上存储位于 GPU 计算芯片内部。高带宽存储器（High Bandwidth Memory，HBM）是部分数据中心 GPU 的显存技术；其他显存方案也有相应供数路径。

| 存储位置 | 归属与管理方式 | 主要用途 |
| --- | --- | --- |
| HBM 显存 | 设备级存储 | 保存模型权重、大型激活和推理状态 |
| 二级缓存（L2 Cache） | 同一 GPU 的 SM 共享，物理上可分片 | 缓存近期访问的数据，减少对显存的重复读取 |
| 一级缓存（L1 Cache） | 各 SM 的局部资源，由硬件管理 | 为局部访问提供缓存 |
| 共享内存（Shared Memory） | SM 内的资源，由程序组织线程块协作使用 | 保存块内反复使用的数据 |
| 寄存器（Registers） | SM 内分配给线程的资源 | 保存操作数、地址和计算中的累加结果 |

**各 SM 拥有局部资源，共享 L2 和设备显存。** 缓存命中可就近取数，共享内存供块内协作复用，寄存器保存操作数与部分结果；具体路径由指令、策略和架构决定。 [来源：NVIDIA GPU Performance Background，GPU 架构；核验于 2026-11-16](https://docs.nvidia.com/deeplearning/performance/dl-performance-gpu-background/index.html#gpu-architecture-fundamentals)

### 容量、带宽与延迟

三项指标分别描述容纳、传输与等待：

| 指标 | 直接含义 | 对推理的影响 |
| --- | --- | --- |
| 容量（Capacity） | 能保存多少数据，常用 GB 或 GiB | 决定模型、上下文状态和中间结果的容纳空间 |
| 带宽（Bandwidth） | 单位时间能传送多少数据，常用 GB/s | 影响持续读取权重和状态的能力 |
| 延迟（Latency） | 一次访问从发起到数据可用所需的时间 | 决定依赖这些数据的计算需要等待多久 |

容量约束模型和状态驻留，数据量与有效带宽约束搬运时间；独立工作交错可覆盖部分访问延迟，机制见第 4 节。

### KV 状态与硬件缓存

注意力为各位置生成键（Key，K）、值（Value，V），保存历史结果供后续生成复用，称为键值缓存（Key–Value Cache，KV Cache）。

KV 通常以张量（Tensor，多维数值数组）驻留显存。KV 是模型状态，L1／L2 是硬件访问缓存；读取 KV 同样经过设备存储系统。

权重、激活和 KV 共同占显存，其访问频率与复用方式决定供数压力。

## 3 计算单元、精度与算力

### 普通运算与矩阵乘加

SM 的普通算术资源执行加减乘、比较和地址计算，加载存储资源完成读写，矩阵资源成批执行乘加。

NVIDIA 张量核心（Tensor Core）执行矩阵乘加：A、B 为输入，C 为已有结果，D 为更新结果。

```text
D = A × B + C
```

矩阵乘加（Matrix Multiply-Accumulate，MMA）是上述基本操作；Kernel 将大矩阵拆成片段，多轮累加形成完整输出。

模型层组合矩阵、普通运算和读写，整体耗时取决于三者的执行组织。 [来源：NVIDIA GPU Performance Background，执行资源与操作类别](https://docs.nvidia.com/deeplearning/performance/dl-performance-gpu-background/index.html)

### 数值格式与混合精度

数值格式规定编码位宽、范围与有效精度。FP32、FP16 分别为 32、16 位浮点，BF16 是另一种范围较宽的 16 位浮点，FP8 为 8 位浮点家族，INT8 为 8 位整数。

低位宽减少存储，配套指令、Kernel 可提高运算吞吐；格式选择同时验证质量、数值范围和硬件支持。

矩阵运算分别注明输入、累加、输出格式。例如某支持路径采用 FP16 输入、FP32 累加，再转输出格式；具体组合由指令和软件决定。 [来源：NVIDIA Mixed Precision，低精度数据与累加](https://docs.nvidia.com/deeplearning/performance/mixed-precision-training/index.html)

### 运算量、峰值与实际吞吐

浮点运算量（FLOPs）计任务运算次数，浮点吞吐（FLOPS）计每秒次数；本章乘、加各计一次，一次乘加共 2 次。

峰值为特定条件下理论上限，须注明型号、输入／累加格式及稠密／稀疏条件；结构化稀疏利用规定零值分布减少工作。

实际吞吐还依赖矩阵形状、并行规模与数据供给；峰值须结合目标工作量判断。 [来源：NVIDIA Matrix Multiplication Background，运算量与矩阵形状](https://docs.nvidia.com/deeplearning/performance/dl-performance-matrix-multiplication/index.html)

## 4 核函数启动与延迟隐藏

### 核函数启动与流

核函数启动（Kernel Launch）是 CPU 提交 GPU 工作，通常异步完成；CPU 继续准备，GPU 按依赖和资源执行。

流（Stream）规定操作顺序：同流顺序执行，跨流在独立、资源充足时可重叠。小 Kernel 较多时，启动、同步与间隙的时间占比更明显。 [来源：CUDA 12.6 编程指南，异步执行](https://docs.nvidia.com/cuda/archive/12.6.0/cuda-c-programming-guide/index.html#asynchronous-concurrent-execution)

### 驻留、就绪与延迟隐藏

线程块获得寄存器、共享内存后，线程束处于驻留状态；操作数、依赖满足时成为就绪工作，SM 调度器从中选指令发往执行单元。

延迟隐藏（Latency Hiding）在一组线程等待时推进另一组就绪工作；可覆盖时间取决于独立工作及资源。

<!-- diagram:03-scheduling -->

此处为 SM 内硬件指令调度；引擎内调度选本轮请求，实例部署调度选设备位置，请求路由选实例。这三层共同决定提交给 GPU 的工作。 [来源：CUDA 12.6 编程指南，硬件多线程](https://docs.nvidia.com/cuda/archive/12.6.0/cuda-c-programming-guide/index.html#hardware-multithreading)

### 占用率与片上资源取舍

占用率（Occupancy）为 SM 驻留线程束占该架构最大驻留数量的比例：

```text
占用率 = 驻留线程束数 ÷ 最大驻留线程束数
```

驻留更多工作可增加就绪候选；单块寄存器、共享内存用量越大，可同时驻留块数可能越少。

更多片上资源支持复用，更多驻留块支持延迟隐藏；结合占用率、访存量和总耗时选配置。 [来源：CUDA 12.6 Best Practices，占用率](https://docs.nvidia.com/cuda/archive/12.6.0/cuda-c-best-practices-guide/index.html#occupancy)

## 5 矩阵分块与合并访存

### 线性投影与复用

线性投影让每个 Token 的特征行与同一权重矩阵相乘，生成新特征，符号如下：

| 符号 | 含义 | 矩阵形状 |
| --- | --- | --- |
| A | 输入特征矩阵，每行对应一个当前参与计算的 Token | M 行、K 列 |
| B | 权重矩阵，将输入特征映射为输出特征 | K 行、N 列 |
| C | 输出特征矩阵 | M 行、N 列 |

M、K、N 分别为本轮 Token 行数、输入特征数、输出特征数，均为数量：

```text
C = A × B
```

C 每个元素是 A 一行与 B 一列的点积。同一 A 行用于多个输出列，同一 B 列用于多个输出行，形成数据复用机会。

### 分块加载与片上累加

分块（Tiling）将大矩阵拆成数据块（Tile）以适应片上空间。先分配 C 输出块，再协作加载所需 A、B 片段。

线程将片段加载到共享内存、寄存器，反复乘加；部分结果留在寄存器，再加载下一组片段，直到处理完全部输入特征后写回。

<!-- diagram:04-tiling -->

图中沿 K 累加：A 的一段列与 B 对应的一段行覆盖相同特征，多轮局部贡献求和得到完整输出。

大块增加复用，也多占寄存器、共享内存；块大小须同时考虑复用和驻留数量。 [来源：NVIDIA Matrix Multiplication Background，分块实现](https://docs.nvidia.com/deeplearning/performance/dl-performance-matrix-multiplication/index.html#gpu-implementation)

### 合并访存与事务效率

合并访存（Coalescing）将多线程访问组织为较少内存事务，即硬件成组处理的读写请求。

同线程束访问连续、对齐地址时更易减少事务；数据布局与线程分工共同决定加载集中程度。

两者分别作用于加载和使用阶段：

| 阶段 | 优化机制 | 直接作用 |
| --- | --- | --- |
| 数据加载时 | 合并访存 | 把多个线程的访问组织得更集中，减少所需事务 |
| 数据加载后 | 分块复用 | 在片上多次使用已加载的数据，减少重复搬运 |

**加载时集中访问，加载后多次复用。** 事务粒度、命中和对齐要求按目标架构确认。 [来源：CUDA 12.6 Best Practices，合并访存与共享内存复用；核验于 2026-11-16](https://docs.nvidia.com/cuda/archive/12.6.0/cuda-c-best-practices-guide/index.html#coalesced-access-to-global-memory)

## 6 推理负载与硬件瓶颈

### 模型操作与硬件工作

注意力（Attention）由输入产生查询 Q（Query）、键 K（Key）、值 V（Value），匹配后汇聚上下文。这里 K 为键矩阵，第 5 节 K 为输入特征数，各用于对应公式。

前馈网络（Feed-Forward Network，FFN）逐位置执行线性、非线性变换。Softmax 将分数归一化为权重；归一化（Normalization）按特征统计调节数值，其中求和、最大值等聚合称为归约（Reduction）。

| 模型操作 | 所做的计算 | 硬件工作 |
| --- | --- | --- |
| QKV 投影、FFN 的线性层 | 输入特征与权重相乘 | 矩阵乘法及权重读取 |
| Attention 的分数计算与信息聚合 | 查询与键匹配，再按权重汇总值 | 矩阵计算及 KV 读取 |
| Softmax、归一化、激活函数 | 统计、缩放与非线性变换 | 归约、逐元素运算与访存 |
| KV Cache 更新 | 保存当前位置计算出的键和值 | 地址定位与 K/V 写入 |

QKᵀ 匹配查询和键，T 表示转置；缩放、遮罩、Softmax 后的权重再与 V 相乘。每步均有相应计算和供数需求。

**历史 KV 读取用于当前 Attention，当前 KV 写入供后续生成复用。**

### 当前行数与权重复用

预填充（Prefill）并行处理已知输入位置，线性层当前行数较多；逐步解码（Decode）每请求每轮处理一新位置。后续输入依赖已生成结果，形成自回归顺序。

批处理（Batching，合批）让多请求共同执行，Decode 的当前 Token 行可共用一次投影中的权重读取。

教学假设：权重矩阵为 4,096 × 4,096，FP16 每元素 2 字节，理想复用时的权重大小为：

```text
4,096 × 4,096 × 2 字节
= 32 MiB
```

MiB 是二进制容量单位，1 MiB = 1,048,576 字节。若在一次投影中，这份权重从所考察的存储层完整读取一次并充分复用：

| 一起计算的 Token 行数 | 本次权重读取量 | 每行平均分摊的权重读取量 |
| --- | --- | --- |
| 1 行 | 32 MiB | 32 MiB |
| 128 行 | 32 MiB | 0.25 MiB |

该估算只计一次充分复用的权重读取；激活、输出、缓存命中与重复加载改变实际流量，算力也影响耗时。**合批计算增权重复用。** [来源：NVIDIA Matrix Multiplication Background，数据复用与矩阵形状](https://docs.nvidia.com/deeplearning/performance/dl-performance-matrix-multiplication/index.html)

### 历史长度与 KV 访问

当前行数描述本轮新位置数量，上下文长度描述每位置需访问的历史。

完整历史 Attention 的 KV 工作量随上下文增长，新位置生成的 KV 追加供后续使用。合批增加当前行数与权重复用，长上下文增加历史处理量。

**长历史多读 KV，新位置追加 KV。** 合批请求仍分别保存、读取自身上下文。

### 业务瓶颈与验证方法

下表列出三类业务的验证重点，影响程度按模型、长度、批次和硬件测量。

| 场景 | 工作特征 | 优先观察 |
| --- | --- | --- |
| 长文档输入 | Prefill 当前行数多，Attention 处理的上下文长 | 矩阵执行效率、Attention 数据搬运和显存占用 |
| 实时对话生成 | 小批次逐步生成，持续访问权重与历史 KV | 数据供给、核函数间隙及每轮生成耗时 |
| Agent 多轮调用 | 请求反复进入和退出，批次与输入长度随时间变化 | 实际合批规模、任务提交节奏和缓存复用情况 |

两组对照分别检验权重与 KV：固定模型、精度、上下文，改批量测吞吐；固定批量、当前行数，增历史测每轮耗时。记录设备、软件、计时边界，预热后重复测量，结论以实测为准。

产品验收同时检查显存覆盖权重与状态、目标负载供数与计算达标、吞吐与交互延迟达标；以请求总耗时评估计算、搬运、等待的共同影响。

**算力、访存、调度共同决定速度。** 第 3 章据此建立性能度量与瓶颈模型。
