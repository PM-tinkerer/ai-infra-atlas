# 第 4 章｜计算与精度优化：降低执行开销

## 1 优化对象与矩阵效率

第 3 章将瓶颈分为计算、数据搬运和执行间隙。本章分别讨论如何减少工作、提高数据复用，以及降低提交和转换成本。实时对话、长文档与智能体（Agent）请求使用同一模型时，最佳执行路径也可能随矩阵形状、历史长度和负载改变。

### 三类执行开销

算子（Operator）描述数学操作，核函数（Kernel）是设备上的实现。一次优化应先说明改变哪一类开销，再选择验证指标。

| 优化方向 | 主要改变 | 需要检查的新增代价 |
| --- | --- | --- |
| 高效矩阵与数据布局 | 提高计算利用率、减少重复读取 | 填充、重排与形状转换 |
| FlashAttention、算子融合 | 减少中间结果读写与启动 | 寄存器、片上空间及实现约束 |
| 编译、执行图重放 | 优化算子组合、减少主机提交 | 编译、捕获、版本及形状管理 |
| 权重与激活量化 | 降低存储位宽，使用适配计算路径 | 缩放、反量化、重排与质量误差 |

同一优化可能同时影响多项。收益用端到端执行和服务指标确认，局部时间线用于解释来源。

### 形状、分块与布局

矩阵乘法的输入形状记为 m × k，权重为 k × n。m 是当前词元（Token）行数，k、n 是输入和输出特征数。更多行有助于复用权重，较小、窄或不规则形状则可能让部分执行资源空闲。

分块（Tiling）将输入片段放入片上存储多次复用；合并访存（Coalescing）让协作线程的访问集中在较少内存事务。块越大，复用机会通常越多，寄存器和共享空间占用也越高，需要结合驻留规模选择。

数据布局（Data Layout）决定元素在内存中的排列。符合内核的对齐、步长和打包方式有助于高效读取；为满足矩阵指令而补齐维度的填充（Padding）会引入额外计算。目标应是减少总耗时，而非仅提高某个算子的峰值比例。[NVIDIA 矩阵形状、分块与执行效率](https://docs.nvidia.com/deeplearning/performance/dl-performance-matrix-multiplication/index.html)（核验于 2026-11-18；具体限制按目标硬件与内核验证）

## 2 FlashAttention 与中间数据搬运

### 标准注意力的数据路径

查询 Q（Query）、键 K（Key）、值 V（Value）由输入投影产生，d 为查询与键的头维度，M 为因果遮罩，O 为注意力输出。单头计算为：

```text
O = softmax(QK^T / √d + M) × V
```

上标 T 表示转置。预填充（Prefill）同时处理 S 个输入位置；Q、K 的形状为 S × d，V 为 S × d_v，d_v 为值向量维度。遮罩 M 为 S × S，可见位置为 0、被遮挡位置为负无穷，输出 O 为 S × d_v。概念上的匹配分数矩阵为 S × S。若分开执行匹配、Softmax 与加权汇聚，可能将大中间矩阵写入显存、再反复读取；其临时容量随长度近似二次增长。

高带宽显存（High Bandwidth Memory，HBM）能保存大量数据，片上静态存储（SRAM）更靠近计算但容量有限。FlashAttention 的核心是在片上分块完成匹配、归一化与汇聚，减少两层存储之间的中间搬运。[FlashAttention 论文 v2：IO 感知与分块](https://arxiv.org/abs/2205.14135v2)

### 在线归一化与精确结果

图中片上工作区逐块遍历可见的 K、V。为同一查询保留最大分数、指数和与未归一化的加权和值；新块改变最大值时，重缩放此前统计，再加入新贡献。全部可见块处理后，以共同分母得到输出。

在线归一化（Online Softmax）使各块服从同一全局权重。教学例：一个查询对应三个分数均为 0，V 的标量值为 2、4、6。前块含 2、4，后块含 6；分别归一化得到 3、6，直接平均为 4.5，而全局三个位置等权时结果为 4。合并必须保留各块的归一化统计。[FlashAttention v2，第 3.1 节与算法细节](https://arxiv.org/html/2205.14135v2)

这里的精确注意力保留完整可见位置的数学语义，浮点运算顺序可能带来舍入差异。减少的是中间存储和 IO；完整长序列注意力的匹配计算仍随序列长度近似二次增长。推理只需前向路径，训练中的反向重计算属于另一部分机制。

解码（Decode）的新查询通常很少、历史 KV 很长，适合的内核组织会与长输入 Prefill 不同。引擎选择时要绑定设备、数据类型、头维度、遮罩、分页布局和模型特性，测量该路径的实际收益。

## 3 算子融合与编译优化

### 融合的工作与资源取舍

算子融合（Operator Fusion）把相邻操作放入同一内核或更紧密的执行路径。例如矩阵结果随后加偏置、做激活：独立实现会写回、再读中间张量，融合可让结果留在寄存器或片上空间，减少读写和启动。

融合增加单核复杂度，也可能增加寄存器需求、降低驻留数量，或失去成熟矩阵库的高效路径。存在跨块同步、复杂分支或不兼容布局时，融合范围还会受限。评估同时比较中间流量、启动数、占用资源和整个算子链时间。

### 编译图与形状专门化

编译优化（Compilation Optimization）分析计算图，选择实现、布局、融合和执行顺序；形状专门化（Specialization）为特定长度、批量或类型生成更合适的代码。它与手写融合关注点相交，但还涉及图提取、代码生成和缓存。

PyTorch 2.7 的 `torch.compile` 连接图捕获与编译后端。图中断（Graph Break）会把可优化区域拆开，输入条件变化可能触发重新编译；具体后端和设备支持以该版本验证。编译时间、首次请求、稳定热态分别计量（核验于 2026-11-18）。[编译器组成](https://docs.pytorch.org/docs/2.7/torch.compiler.html)、[图中断与重编译](https://docs.pytorch.org/docs/2.7/torch.compiler_troubleshooting.html)

对在线服务，可覆盖高频形状并为少见形状保留可用路径。分桶（Bucketing）把若干长度或批量归到固定规格，能提高复用，但需要核算填充开销和桶间切换。输入变化频繁时，维护大量专门化配置可能增加冷启动及发布成本。

## 4 CUDA Graphs 与提交开销

### 捕获、实例化与重放

CUDA Graphs 是 NVIDIA CUDA 中的执行组织机制：把核函数、拷贝等操作及依赖定义成图，准备后重复启动，减少逐项主机提交。CUDA 12.6 支持显式建图及流捕获等方式，图的定义、准备和执行是不同阶段。[CUDA 12.6 Graphs](https://docs.nvidia.com/cuda/archive/12.6.0/cuda-c-programming-guide/index.html#cuda-graphs)（核验于 2026-11-18）

若一个解码轮次有许多短内核，CPU 提交与同步间隙可能明显；重放可以缩短这些间隙。图内实际矩阵与 KV 读取仍需执行，因此收益依赖原提交开销占比。其他加速器的执行图机制应分别核验。

### 动态服务的重放条件

持续生成的批量和序列长度会变化，重放需要符合对应形状、参数、地址与依赖的约束；具体可更新范围按 API 与引擎实现确认。准备多个规格、预分配缓冲和填充输入，是常见的组织思路。

图相关缓冲与捕获记录会占用内存。上线验收应包含捕获耗时、命中规格比例、回退路径、额外显存，以及取消和批次变化后的正确性；热态加速与实例准备时间共同影响弹性供给。

## 5 权重与激活量化

### 数值映射与误差

量化（Quantization）用较低位宽编码数值。权重是固定参数，激活是输入相关的中间表示；两者的分布、离群值与运行时处理成本不同。

以仿射整数映射为教学模型：原数值为 x，正缩放系数为 s，整数零点为 z，编码为 q，重建值为 x_hat。s 与 x 同量纲，q、z 为无量纲整数，q_min、q_max 为编码范围：

```text
q = clip(round(x / s) + z, q_min, q_max)
x_hat = s × (q − z)
```

round 是取整，clip 是范围截断。教学假设 s = 0.1、z = 0、x = 0.26，得到 q = 3、x_hat = 0.3，绝对误差为 0.04。实际分组、逐通道或浮点量化使用相应规则，这个例子只解释有限表示与误差来源。

校准（Calibration）用代表性数据确定缩放与相关参数。异常大值会影响量化范围，长文档、稀有格式和 Agent 工具参数需要单独评估。SmoothQuant 通过等价变换平衡权重、激活的量化难度，是权重与激活均采用 8 位（W8A8）的后训练量化方法实例，不代表所有低精度实现都采用同一路径。[SmoothQuant 论文 v7](https://arxiv.org/abs/2211.10438v7)

### 存储格式与计算路径

W4A16 表示权重 4 位、激活 16 位，W8A8 表示两者均 8 位；还须注明整数或浮点、分组方式、缩放、累加和输出精度。相同位宽标签可能对应不同打包格式和内核。

| 路径 | 可能收益 | 验证重点 |
| --- | --- | --- |
| 低位宽权重，较高精度计算 | 减少权重驻留和读取 | 解包、反量化是否抵消节省 |
| 权重与激活低精度计算 | 同时减少数据量并利用适配指令 | 激活量化成本、累加精度和内核覆盖 |
| 特殊层保留较高精度 | 保护敏感输出和任务质量 | 转换边界、实际加速层占比 |

第 3 章的 8B 教学模型，2 字节权重为 16 GB；理想 4 位数据部分为 4 GB，约 3.73 GiB。实际还含缩放、零点、对齐、部分高精度层及临时空间。释放显存可能先增加 KV 或并发空间，速度收益仍受形状、带宽和转换约束。

## 6 局部优化与端到端收益

### 耗时占比与新增成本

Amdahl 定律（Amdahl's Law）说明局部加速受原耗时占比限制。设基线时间为 T，目标部分占比为 f，加速倍数为 a，其他部分不变，新增转换或协调时间为 ΔT，时间单位一致，则：

```text
T_new ≈ T × [(1 − f) + f / a] + ΔT
A_end = T / T_new
```

教学假设 T = 100 ms，f = 0.6，a = 2，ΔT = 5 ms，得到 T_new = 75 ms，端到端加速约 1.33 倍。若目标只占 10%，即使局部耗时几乎消除，其他 90% 仍然存在。

该式是固定工作量、可分解路径的近似。真实系统可能改变重叠、批量与瓶颈，应以新时间线重测；排队也会随负载变化，所以单次执行收益与在线 TTFT、Goodput 分别验收。

### 组合优化与瓶颈迁移

融合和 FlashAttention 可能减少同一部分搬运，编译与 CUDA Graphs 可能覆盖相近提交开销，收益相交时不能将倍数直接相乘。量化释放显存后增加批量，也会改变算子形状和调度。

先单项验证机制，再对计划上线的组合重放负载。每次记录质量、时延、吞吐、峰值显存、首次准备时间和回退比例，确认优化没有把压力转移成另一个不可接受的边界。

## 7 场景验证与产品选择

### 优化对照设计

| 业务与瓶颈 | 候选改动 | 同条件验证 |
| --- | --- | --- |
| 长文档 Attention 中间流量大 | 适配的精确注意力内核 | 相同上下文、遮罩和质量，测 Attention 与 TTFT |
| 小批对话内核间隙明显 | 融合、编译或图重放 | 相同批次与输出长度，测 CPU/GPU 轨迹及 ITL |
| 权重容量或读取受限 | 权重量化及适配内核 | 相同任务质量，测转换、内存和逐轮耗时 |
| Agent 输入形状反复变化 | 形状覆盖、编译缓存与回退设计 | 真实调用轨迹，测冷态、重编译与任务总时延 |

数值验证先比较固定输入的算子或层输出，再测任务集及真实采样；使用业务认可的误差和成功条件。工具调用字段、类型、停止原因及长文档证据提取要覆盖。长时间运行还需检查缓存、显存增长与规格切换。

### 可交付的优化配置

优化交付绑定模型修订、精度制品、硬件、驱动、内核后端、编译和图模式、支持形状、质量结果及负载范围。通用机制可以迁移理解，具体 CUDA、Tensor Core 和版本支持分别记录。

平台应选择在目标业务上产生可验证净收益的组合：对话满足尾部输出间隔，文档满足首次等待与上下文质量，Agent 满足任务成功。**少计算、少搬运、少提交各有机制，最终收益由完整执行路径验证。**
