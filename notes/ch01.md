# 第 1 章｜大模型推理原理：从输入到逐 Token 生成

## 1 请求链路与自回归生成

### 上下文与文本编码

模型输入由系统指令、历史、检索文档、当前问题和格式标记共同组成。完整输入经编码、嵌入和多层计算，产生下一个词元的候选分数。

<!-- diagram:01-request -->

| 环节 / 术语 | 含义 | 对推理产品的意义 |
| --- | --- | --- |
| Token / Token ID | 文本编码单位及其整数编号，不固定等于一个字或单词 | 按真实分词后的长度计量负载 |
| Tokenization / 分词编码 | 将文本及格式标记转换为模型输入编号 | 分词器和对话模板须与模型匹配 |
| Embedding / 嵌入 | 将每个编号映射为维度为 d_model 的向量 | 向量进入网络，不是直接处理文字 |
| Hidden state / 隐藏状态 | 每层变换得到的中间向量表示 | 不等于模型权重或最终答案 |
| Logits / 输出分数 | 输出层对词表候选产生的未归一化分数 | 还需按生成策略选出 Token |
| Sampling / 采样 | 根据概率分布选择候选；贪心选择则取最高分 | 影响多样性与可复现性 |
| EOS / 结束标记 | 一种结束生成的条件，另有长度上限等条件 | 输出长度是上限而非必然生成量 |
| Detokenization / 反分词 | 将输出 Token 序列转换回可显示文本 | 网络流式片段与 Token 不必一一对应 |

### 自回归与顺序依赖

输入记为 x_1,…,x_S，S 为输入长度；y_t 为第 t 个输出。**自回归生成**按 P(y_t | x_1,…,x_S, y_1,…,y_(t−1)) 选择下一输出，依赖此前已选结果。生成轮次有先后，轮内计算仍可并行；普通推理只执行前向计算，权重保持固定。 [来源：文本生成](https://huggingface.co/docs/transformers/main/en/llm_tutorial)

### 输入长度估算

教学假设：系统及模板 300 + 历史 1,200 + 文档 8,000 + 当前问题 30 = 9,530 个输入 Token。推理负载按完整输入计，检索和历史保留策略会改变这一长度。



## 2 Transformer 层与注意力

### 层结构与残差连接

**注意力（Attention）汇聚上下文，前馈网络（Feed-Forward Network，FFN）变换各位置特征。** 以下采用先归一化（Pre-Norm）层结构，具体模型布局可能不同。

<!-- diagram:02-transformer -->

残差连接将子层输入加到结果上，LayerNorm、RMSNorm 等归一化（Normalization）调节特征尺度。图中 x 为层输入，h、z 为两次残差输出：h = x + Attention(Norm(x))，z = h + FFN(Norm(h))。多层之后经输出层得到词表分数。

### QKV、模型参数与注意力权重

查询 Q（Query）表达匹配需求，键 K（Key）用于计算匹配分数，值 V（Value）提供待汇聚信息；三者均由输入投影得到。

| 对象 | 如何产生 | 普通推理时的特点 |
| --- | --- | --- |
| 模型参数 W（Model Weights） | 训练学习得到，如 W_Q、W_K、W_V、W_O | 固定，同一层的参数可在位置和请求间复用 |
| Q、K、V 中间表示 | 输入表示乘以相应投影参数 | 随输入而变化 |
| 注意力权重 A（Attention Weights） | Q 与 K 的匹配分数经 Softmax 归一化 | 随当前查询而变化，决定汇聚各位置 V 的比例 |

单头注意力按“投影 → 匹配 → 汇聚”计算。X 为投影输入，d_k 为 Q/K 头维度，M 为因果遮罩，A 为注意力权重，O 为汇聚输出；省略偏置和位置编码。

```text
Q = XW_Q,  K = XW_K,  V = XW_V
A = softmax(QK^T / √d_k + M)
O = AV
```

因果遮罩 M 在可见位置取 0、未来位置取 −∞；Softmax 将匹配分数归一化为上下文位置权重 A，随后用于汇聚 V。词表分数由后续输出层产生，用于选择下一个 Token。

教学例：若一个查询对三个位置的权重为 [0.1, 0.2, 0.7]，对应 V 为 [2, 0]、[0, 2]、[2, 4]，则汇聚结果为 0.1×[2, 0] + 0.2×[0, 2] + 0.7×[2, 4] = **[1.6, 3.2]**。

多头独立计算，拼接后乘输出投影 W_O，混合各头特征，再进入残差与后续层。 [来源：Transformer 原论文 §3.2](https://arxiv.org/html/1706.03762v7#S3.SS2)

### FFN 与位置编码

FFN 对各位置应用同一组非线性变换：FFN(x) = activation(xW1+b1)W2+b2，W1、W2 为权重，b1、b2 为偏置，activation 为激活函数；现代模型也常用门控形式。各位置独立执行，输入已包含 Attention 汇聚的上下文。 [来源：Transformer 原论文](https://arxiv.org/abs/1706.03762)

位置编码提供顺序信息，可用绝对位置嵌入；旋转位置编码（Rotary Position Embedding，RoPE）按位置旋转 Q、K，使点积表达相对位置。其作用于 Q/K 的方式与向量相加不同，长上下文质量须另行验证。 [来源：RoPE 原论文](https://arxiv.org/abs/2104.09864)


## 3 Prefill、Decode 与 KV Cache

### 执行阶段与生成顺序

预填充（Prefill）在因果遮罩下并行处理已知输入，完成后选择首输出；逐步解码（Decode）每轮处理刚选出的 Token、预测下一 Token。轮次按输出依赖推进，步内及不同请求间可并行。

<!-- diagram:03-cache -->

| 阶段 | 本轮输入 | 本轮新增 KV | 本轮选出的输出 |
| --- | --- | --- | --- |
| Prefill | Prompt 各位置 | Prompt 各位置的 KV | y1 |
| 第 1 轮 Decode | y1 | y1 的 KV | y2 |
| 第 2 轮 Decode | y2 | y2 的 KV | y3 |

缓存对应本轮输入位置。y3 触发结束后无需再次送入模型，也无需生成它的 KV。完整 Prefill、非投机逐词元流程产生 N 个输出时，通常执行一次 Prefill、N−1 轮 Decode。 [来源：文本生成](https://huggingface.co/docs/transformers/main/en/llm_tutorial)

### 历史 KV 的复用条件

键值缓存（Key–Value Cache，KV Cache）保存各注意力层、各 KV 头已投影的 K、V，依赖权重、输入和位置。它是第 2.2 节的中间表示；采用 RoPE 时，K 通常已旋转。

**因果注意力使旧位置不依赖未来。** 权重、历史前缀和位置条件固定时，追加 Token 保持旧表示不变；Decode 只投影当前 Q/K/V、追加新 KV，复用历史 KV。

每轮仍需用当前 Q 匹配历史 K、加权汇聚 V，并执行输出投影和 FFN。下一轮使用新 Q，历史 Q 通常无需缓存。 [来源：Hugging Face KV Cache 原理](https://huggingface.co/docs/transformers/main/en/cache_explanation)

逻辑追加可用预分配或分页写入实现；滑窗、量化、搬移改变物理存储，前缀缓存进一步支持请求间复用，详见第 5 章。

### Decode 的权重与 KV 访问

小批量 Decode 常受显存带宽限制（Memory-bandwidth-bound）：权重和 KV 的供数速度约束计算。新增 KV 写入与历史 KV 读取规模分别核算；带宽描述搬运速度，容量描述可驻留数据量。

| 每轮工作 | 主要数据访问 | 为什么有开销 |
| --- | --- | --- |
| 投影、FFN 等计算 | 读取当前激活的模型权重 | 一个新位置仍要经过大矩阵计算 |
| Attention 匹配与汇聚 | 读取可访问位置的 K、V | 缓存省去历史重算，没有省去对历史的访问 |
| 缓存当前输入 | 写入一个位置的新 K、V | 长上下文下，写入通常远小于历史 KV 的逻辑读取规模 |

Prefill 多位置、Decode 多请求合批（Batch）均可复用权重；各请求通常维护独立 KV，历史访问需分别计量。第 4.3 节给出缓存算例。 [来源：推理中的线性运算与 Attention 分析](https://jax-ml.github.io/scaling-book/inference/)

短上下文可能以权重读取为主，长上下文可能以 KV 访问为主；瓶颈还取决于批量、模型、精度、算子、硬件及通信。第 3 章进一步估算算术强度与瓶颈。


## 4 模型结构与缓存容量

### Dense 与 MoE

Dense／MoE 描述稠密执行与专家选择，MHA／GQA／MQA 描述 KV 头共享；两组机制可组合。

<!-- diagram:04-models -->

稠密模型（Dense）让同层 Token 通常经过同组 FFN；混合专家（Mixture of Experts，MoE）以多个专家替代部分 FFN，由路由器（Router）选择、加权组合，也可包含共享专家。 [来源：Switch Transformers](https://arxiv.org/abs/2101.03961)

MoE 总参数决定权重驻留或调入需求，每 Token 激活参数影响计算；端到端收益还取决于专家分布、负载均衡和跨设备通信。

### MHA、GQA 与 MQA

| 注意力结构 | 英文全称 | 例：8 个 Query 头 | 主要含义 |
| --- | --- | --- | --- |
| MHA | Multi-Head Attention | 8 个 K/V 头 | 每个 Q 头有对应 K/V 头 |
| GQA | Grouped-Query Attention | 例如 2 个 K/V 头 | 每 4 个 Q 头共享一个 K/V 头 |
| MQA | Multi-Query Attention | 1 个 K/V 头 | 所有 Q 头共享一个 K/V 头 |

同层数、长度、头维度和精度下，KV 头越少，缓存容量越小。GQA 的 KV 头数介于 MHA、MQA 之间，质量与速度按配置验证。 [来源：GQA 原论文](https://aclanthology.org/2023.emnlp-main.298/)

### KV 容量与并发估算

**KV Cache 容量估算**（各层配置相同、标准 K/V 存储、K 与 V 维度相同）：

L：注意力层数；H_kv：每层 K/V 头数；d_h：每头维度；b：每元素字节数；S_i：第 i 个请求已缓存的位置数。系数 2 表示 K 和 V 两份。若 B 个请求长度均为 S，则 ΣS_i = B×S。

```text
M_KV = 2 × L × H_kv × d_h × b × Σ S_i  （字节）
```

教学假设：L=32、H_kv=8、d_h=128、b=2，且不做跨卡切分。以下均汇总所有注意力层，1 KiB = 1,024 字节，1 GiB = 1,024³ 字节。

| 规模 | KV 数据量 | 对应含义 |
| --- | --- | --- |
| 一个位置 | 131,072 字节 = 128 KiB | 每个新增输入位置对应的 KV 增量 |
| 一个请求，已缓存 8,192 个位置 | 1 GiB | 该请求历史 KV 的容量；全注意力每轮需访问这些历史 K/V |
| 16 个同长度请求 | 16 GiB | 并发请求的缓存容量相加 |

新增一个位置的写入远小于长历史访问规模。1 GiB 为逻辑量，实际总线流量受片上缓存、复用、量化和重复读取影响；仅将 H_kv 从 8 改为 32，理论容量增为 4 倍。

总显存另计权重、激活、工作区、页表、碎片与量化元数据；单卡按分片或复制重算，滑窗、压缩注意力、异构层配置按实际结构修改公式。



## 5 延迟指标与业务取舍

### 延迟与吞吐指标

<!-- diagram:05-latency -->

| 指标 | 含义 | 使用时的注意事项 |
| --- | --- | --- |
| TTFT | Time to First Token，首 Token 延迟 | 明确从客户端发送还是服务端收到请求计时 |
| ITL | Inter-Token Latency，Token 间延迟 | 关注波动与分位数，不只看平均值 |
| TPOT | Time Per Output Token，平均输出 Token 耗时 | 常见口径为首 Token 后耗时除以 N−1，需核对工具定义 |
| E2E latency | 端到端延迟 | 除模型外还可能包含排队、网络、格式处理等 |
| Throughput | 单位时间完成的请求数或 Token 数 | 单请求速度与系统总吞吐要分开衡量 |

### 延迟分解与算例

N 为输出 Token 数，ITL_j 为第 j 个相邻输出间隔，T_末Token 为请求至末 Token 的时长。观测边界一致、N>1 且首末到达时间可见时：

```text
T_末Token = TTFT + Σ ITL_j
          = TTFT + (N−1) × 平均 ITL
```

若端到端计时含结束信号或后处理，另加相应耗时；多 Token 片段的间隔按逐词元口径换算。容量预测中的未来平均 ITL 仍须估计。

教学算例：TTFT=0.4 秒，平均 ITL=0.02 秒，N=100，则到末 Token 约 0.4+99×0.02=2.38 秒，仅演示时间分解。

### 输入输出长度与产品选择

| 业务情境 | 主要增加的工作 | 产品侧可采取的方向 |
| --- | --- | --- |
| 长文档、短摘要 | Prefill 工作量与上下文缓存 | 检索筛选、上下文组织、可复用前缀 |
| 短提示、长报告 | 更多按步推进的 Decode | 合理输出长度、分阶段交付、离线模式 |
| 长对话 | 每轮上下文可能继续变长 | 历史管理、摘要与质量验证 |
| 大量并发 | 聚合计算、缓存占用和排队 | 后续引擎调度、准入与容量规划 |

8,000 输入＋200 输出比反向长度组合需要更多 Prefill 工作，200 输入＋8,000 输出需要更多 Decode 轮次。总耗时还须结合模型、硬件、Batch、缓存和排队判断。

流式输出提前展示内容，模型仍完成生成；缩短实际输出可减少步骤，需同时验证任务完成。温度、top-k、top-p 控制 Token 选择，性能收益按实际生成路径测量。
